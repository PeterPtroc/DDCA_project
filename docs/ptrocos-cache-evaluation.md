# I/D cache 评估

视频阶段完成后，使用独立性能固件测量两种 PC 实现。CPU 与既有 RTL 保持冻结，未加入 cache。复现入口为 `scripts/test_ptrocos_perf.ps1`；精确结果与请求地址记录见 [缓存评估验收](ptrocos-cache-validation.json)。

| 场景 | CSR 周期 | DDR 等待比例 |
| --- | ---: | ---: |
| 寄存器循环 | 5129 | 0% |
| ROM / BRAM 读 | 7200 / 7201 | 0% |
| DDR 热读 / 顺序读 | 31235 / 31219 | 76.9% |
| DDR 顺序写 | 8832 | 82.4% |
| DDR 指针追踪 | 31725 | 70.9% |
| DDR 热读与 DMA | 40838 | 82.3% |

两种实现各运行 9 个场景，总计 336624 周期。计数窗口用既有 GPIO 标记，同时比较固件 CSR 与测试台退休记录；先后读取两个 CSR 有窗口偏移，不能直接据短场景计算 CPI。

当前指令从同步 BRAM 一周期返回，I cache 不会消除 DDR 数据等待。对已完成请求作冷启动地址重放，假设 1/4 KiB 直接映射、16 字节行、读分配、直写且不写分配：热读与指针追踪命中 93.75%，4 KiB 单次顺序读命中 75%。这只是地址命中率，未模拟 refill、缓存 RTL、MIG 延迟或 DMA 一致性，不能报告为实际加速。

以后若实现 D cache，须明确可缓存区、完成握手、错误与取消语义；MMIO 始终旁路，framebuffer、视频环和 DMA 共享区默认无缓存。CPU 写入在 DMA 启动前完成，DMA 修改缓存区后须失效对应行；回写策略还须提供清理。重新覆盖精确 trap、字节写、DMA 竞争、视频扫描与物理时序后才能启用。
