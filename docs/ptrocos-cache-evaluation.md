# I/D cache 评估

第 10 阶段提交 `2894f42` 后，先测量现有无缓存系统。原 CPU、RV32IM 内存核心、SoC RTL、FreeRTOS 内核和视频固件源码保持不变；新增 `perf` 裸机固件、仿真观察器和地址重放分析。评估记录见 [ptrocos-cache-validation.json](ptrocos-cache-validation.json)。

当前决定：保留现有 BRAM 取指路径，暂不实现 I cache；D cache 留待 ELF 应用的真实访问模式和内存映射确定后选择。DDR 热读微基准已有明显等待，但当前媒体数据、文件工作区和内核仍在 BRAM，图形帧缓冲主要由 CPU 写入、VGA 读取。地址命中潜力不足以单独证明实际 Bad Apple 播放需要缓存，实卡播放仍待验。第 11 阶段完成的是测量与设计取舍，没有加入缓存，也不修改第 10 阶段位流。

## 复现

```powershell
.\scripts\build_ptrocos.ps1 -Firmware perf -ToolchainPrefix <riscv-none-elf前缀>
.\scripts\test_ptrocos_perf.ps1
python sw/tools/analyze_ptrocos_perf.py
```

`perf` 是独立的仿真性能固件，ROM 2880 字节，BSS 1040 字节。它通过已有 GPIO 结果寄存器标记测量窗口，使用已有 `mcycle/minstret` CSR 输出结果。测试台从同一个窗口同时统计周期与退休指令，记录 DDR 请求的完整地址、读写方向、等待周期和 DMA 传输数量。原 CPU 不增加观测端口。每个场景的校验和、访问次序和请求数量分别由固件和独立 Python/SV 检查。

模型采用 CPU 100 MHz、UI 周期 12.307 ns、完整地址标记的稀疏 AXI 存储器，AW/W/B/R 延迟各自独立。两种 PC 实现各通过 9 个场景，每种总计 336624 周期、4608 次 DDR 读和 2048 次 DDR 写，包含初始化及 DMA。DMA 复制的 256 个数据字还由存储器模型逐项核对。

## 结果

两种 PC 实现的数据一致。下表周期与退休数是固件 CSR 读数；等待比例使用测试台同一窗口的计数。

| 场景 | 访问量 | CSR 周期 | CSR 退休数 | DDR 等待比例 |
| --- | --- | ---: | ---: | ---: |
| 寄存器循环 | 1024 次累加 | 5129 | 3088 | 0% |
| ROM 读 | 1 KiB，重复 4 次 | 7200 | 4132 | 0% |
| BRAM 读 | 1 KiB，重复 4 次 | 7201 | 4133 | 0% |
| DDR 热读 | 1 KiB，重复 4 次 | 31235 | 4132 | 76.917% |
| DDR 顺序读 | 4 KiB，一次 | 31219 | 4123 | 76.934% |
| DDR 顺序写 | 1 KiB，一次 | 8832 | 1041 | 82.374% |
| DDR 指针追踪 | 1 KiB，步长 37，1024 次依赖读 | 31725 | 6160 | 70.893% |
| DDR 热读与 DMA | 1024 次读，DMA 同时复制 256 字 | 40838 | 4138 | 82.324% |

空测量的 CSR 周期为 9、退休数为 14。两个 CSR 必须先后读取，起止窗口错开，短场景不能直接把二者相除当作 CPI。JSON 的 `cycles_per_retired` 使用测试台同一窗口的计数。`load_use` 和 `m_wait` 是原内部信号的有效周期，可能与 DDR 等待重叠，不能把这些列相加当作额外停顿。

当前取指由同步 BRAM 直接提供一周期响应，没有外部取指 ready 接口。加 I cache 不会消除上述 DDR 数据等待。ROM/BRAM 数据访问没有外部总线等待；DDR 读写需要跨域握手及 AXI 完成，测量结果显示这是这些微基准的主要等待来源。

## 地址重放与后续条件

分析器对已完成的 CPU DDR 请求重放两种假设：1 KiB/4 KiB 容量、16 字节行、直接映射、读分配、直写且不写分配，每个场景冷启动。16 字节对应现有 AXI beat，但当前 CPU 返回接口只提供一个数据字；实际缓存的放置、整行返回、填充和错误恢复还需要设计。

| 场景 | 1 KiB / 4 KiB 假设缓存的读命中 |
| --- | --- |
| DDR 热读、指针追踪、DMA 竞争热读 | 960/1024，93.75% |
| DDR 4 KiB 单次顺序读 | 768/1024，75% |
| DDR 顺序写 | 256 次直写；不以读命中隐藏写等待 |

这些是地址命中率，没有模拟 refill 周期、缓存 RTL、MIG 实时延迟或 DMA 一致性，不能报告为实测加速。性能固件未运行 FreeRTOS、SD 流式读取或 VGA 扫描，因此本阶段不推断板卡上的完整媒体帧率。

以后若加入 D cache，需先固定可缓存区和应用所有权，满足以下条件再启用：

- MMIO、CLINT、SD/UART/FIFO 和图形控制寄存器始终旁路，不提前执行带副作用的读取。
- VGA 帧缓冲、视频帧环和 DMA 共享区默认保持无缓存；不能仅用 front 交换代替数据一致性。
- DMA 启动前完成 CPU 写入；DMA 修改可缓存区时失效对应行。若选择回写，还需明确清理、失效和 fence 的完成握手。
- 数据访问 fault 不安装缓存行，取消或复位清除未完成填充；保留字节/半字写语义及精确 trap。
- 复用已验证的原 CPU，通过独立模块试验缓存；重新覆盖两种 PC 实现、MMIO 单次提交、DMA 竞争、图形扫描与物理时序。

ELF loader 将先明确可执行窗口、数据范围、BSS 清零和调用/返回约定。当前 CPU 的取指高地址不能直接当作 DDR 可执行内存使用；必须先建立真实的可执行映射，再验证程序交接。缓存评估不能代替这一步。
